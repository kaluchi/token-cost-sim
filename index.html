LLM Token Cost Simulator

Меньше итераций — меньше счёт

LLM API stateless: каждый вызов принимает весь контекст с нуля. Ниже четыре интерактивных модели, которые показывают, как это превращает количество вызовов в главный фактор стоимости сеанса.

01

Где прячется x²-парабола

Контекст растёт линейно, а суммарный input за сеанс — как парабола. Откуда берётся N² и почему удвоение вызовов учетверяет стоимость.

  • Суммарный input растёт как N²
  • 2× вызовов → ~4× стоимость
  • Визуальная «лестница» input на каждый вызов
  • Распределение стоимости сеанса с Prompt Caching
Подвигайте N и δ — увидите параболу
02

Длительный vs Объёмный контекст

Много мелких итераций или мало крупных — при одинаковом финальном контексте стоимость разная.

  • Много мелких итераций → квадратичная переплата
  • Крупный контекст, мало итераций → дешевле
  • Prompt Caching сжимает стоимость повторного input
  • Break-even: при каком N итерации выгоднее
Сравните два сценария с одинаковым результатом
03

One-Shot: всё за один вызов

Если проект влезает в контекст — зачем итерировать? N = 1 → нет квадратичного роста.

  • Средний файл с кодом ≈ 1.5k tokens
  • Микросервис (50–80 файлов) → полностью влезает в 200k
  • Калькулятор: влезает ли ваш проект?
  • Break-even: с какого N итерации дороже one-shot
Проверьте: влезает ли ваш проект в один вызов?
04

Фиксированный налог

Системный промт летит в каждом вызове целиком. Чем больше итераций — тем больше раз вы за него платите.

  • Какая доля стоимости — налог, какая — полезные данные
  • Два пути к одному контексту: мелкие vs крупные шаги
  • Техники: batch reads, bash chaining, unified diffs
  • Crossover: при каком N крупные шаги окупаются
Разложите стоимость на налог и полезную работу
⚡

N² против N

Размер промта, объём tool results и цена за токен влияют на стоимость линейно. Число вызовов влияет квадратично: каждый новый вызов несёт в себе весь контекст всех предыдущих. Сокращение промта даёт пропорциональную выгоду. Сокращение числа вызовов даёт непропорционально бо́льшую, потому что убирается не только сам вызов, но и его тень во всех последующих.
