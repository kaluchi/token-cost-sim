One-Shot: всё за один вызов

Если проект влезает в контекст — зачем итерировать? Один вызов с полным контекстом: N = 1, квадратичного роста нет.

🎯

Вырожденный случай: N = 1

One-Shot — крайний случай: один вызов, весь контекст сразу. Контекст обрабатывается один раз, квадратичного роста нет. Стоимость = input × цена за токен + output × цена за токен.

Стоимость: N итераций vs One-Shot
Квадратичная кривая итеративного подхода пересекает горизонталь One-Shot. До пересечения — итерировать дешевле, после — дороже.
Суммарный input: итерации vs one-shot
One-Shot обрабатывает контекст ровно один раз. Итеративный подход обрабатывает его N раз → параболический рост.

Типичные проекты (только исходный код, без node_modules/dist)
  • Микросервис / CLI-тул (20–60 файлов src): ~25k–80k tokens → полностью влезает в 200k
  • Среднее веб-приложение (100–250 файлов src): ~120k–300k tokens → нужна фильтрация релевантных файлов
  • Монорепо / крупный проект (500+ файлов): one-shot по всему проекту невозможен, но подмножество для конкретной задачи обычно влезает
Когда one-shot выгоднее итераций
  • Проект влезает целиком и задача затрагивает большую часть кода — загрузить всё дешевле, чем искать нужное итерациями
  • Задача затрагивает много файлов — если агенту нужно прочитать 40+ файлов, одношотовая загрузка дешевле 40 итераций grep → read
  • Рефакторинг / rename — одна загрузка всех файлов позволяет предложить все изменения сразу, без пошагового поиска
  • Code review — загрузить весь diff + затронутые файлы в один вызов
Когда итерации лучше
  • Точечный баг-фикс — затронут 1–2 файла, остальные не нужны
  • Разведка / exploration — непонятно заранее, какие файлы нужны
  • Проект не влезает — 500+ файлов, нужна целевая навигация
