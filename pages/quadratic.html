Где прячется x²-парабола

LLM API stateless — каждый вызов принимает весь контекст целиком. Контекст растёт линейно, но суммарный input за сеанс растёт квадратично.

📐

Ключевой механизм

LLM API тарифицирует каждый вызов по размеру входного контекста. Контекст растёт на δ токенов за вызов → вызов k обрабатывает S + k·δ. Суммарный input за N вызовов = S·N + δ·N(N−1)/2 ≈ δ·N²/2 — это сумма арифметической прогрессии, площадь трапеции, интеграл линейной функции. Одна и та же парабола, три разных языка.

Три языка одной параболы

1. Арифметическая прогрессия

Input каждого вызова: S, S+δ, S+2δ, ..., S+(N−1)δ — арифметическая прогрессия с разностью δ.

Σ = N·S + δ·(0 + 1 + 2 + ... + (N−1)) = N·S + δ · N·(N−1)/2 ≈ S·N + δ·N²/2 при больших N
2. Площадь трапеции

Представь ось X = номер вызова, ось Y = размер input. Получается трапеция с основаниями S (первый вызов) и S + N·δ (последний) и высотой N. Площадь = суммарный input:

Площадь = (S + (S + N·δ)) / 2 × N = S·N + δ·N²/2

Прямоугольник высотой S — это фиксированный налог (повторная передача начального контекста). Треугольник сверху — это квадратичная переплата за растущие данные.

3. Интеграл

В непрерывном приближении input(x) = S + δ·x, x ∈ [0, N]:

∫₀ᴺ (S + δ·x) dx = S·x + δ·x²/2 |₀ᴺ = S·N + δ·N²/2

Та же формула. Интеграл = площадь под графиком = суммарный input = стоимость.

Почему это важно
  • 2× вызовов → ~4× стоимость (квадратичный член доминирует)
  • Prompt Caching снижает стоимость повторной передачи старого контекста до ~10%, сжимая квадратичный коэффициент в ~10×
  • Меньше вызовов (крупные шаги, качественный промт) — квадратичный эффект делает это эффективнее оптимизации размера контекста
  • При фиксированном финальном контексте: меньше вызовов → дешевле
